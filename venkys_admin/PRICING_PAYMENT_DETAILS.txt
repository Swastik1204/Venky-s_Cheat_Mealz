PRICING + PAYMENT DETAILS (Admin App: venkys_admin)

This section describes how pricing is entered/derived in Admin and how it relates to customer-side ordering.

1) Pricing fields

Simple pricing (no variants)
- `rate` (₹): selling price (required)
- `price`: stored equal to `rate`
- `mrp` (₹): optional
- `discountPercent` (%): optional

Variant pricing
- Enable "Variants" in the Edit Item modal.
- Each variant requires a name AND a valid Rate.
- Variant object stored to Firestore contains:
  - `name` (string)
  - `rate` (number)
  - `price` (number) = `rate`
  - `mrp` (number, optional)
  - `discountPercent` (number, optional)

2) Auto-calculation behavior (important)

Admin will auto-calculate missing values when possible:
- If Rate + Discount are set → MRP can be derived.
- If MRP + Discount are set → Rate can be derived (this is the common flow requested for variants).
- If MRP + Rate are set → Discount can be derived.

Derived values are rounded to whole rupees.

3) Variant mode: Rate not manual anymore

In Variant mode, you can enter MRP and Discount and the Rate field will populate automatically.
Also, when switching from Simple → Variants, the first variant row is prefilled with the Simple pricing values to reduce manual entry.

4) "Size Variant" (suffix builder)

In the variant editor row:
- You always type the base variant name in the text box.
- If you toggle "Size Variant" ON:
  - you pick one of: Half / Full / Pcs
  - if Pcs is selected, you enter a number
  - the final stored variant name becomes:
    - "{BaseName} Half"
    - "{BaseName} Full"
    - "{BaseName} 6 Pcs"
  - (if BaseName is empty, the name is just the size, e.g. "Half" or "6 Pcs")

Note: "Pcs" is intentionally NOT offered in the generic variant-name suggestions list to avoid accidental naming; it remains available only through the Size Variant controls.

5) Customer visibility

Customer app reads the same `menu` data and explodes variants into separate visible items, so customers see each variant as a separate product with the variant pricing.

6) Payment endpoints

For Razorpay, see:
- create order: /api/create-order
- verify signature: /api/verify-payment

7) Key environment variables

- RAZORPAY_KEY_ID
- RAZORPAY_KEY_SECRET
- CORS_ORIGIN
- WA_TOKEN
- WA_PHONE_NUMBER_ID
