PRICING + PAYMENT DETAILS (Customer App: venkys)

This section describes how pricing fields and payment endpoints work in this project.

1) Pricing model (menu items)

Each menu item (from Firestore collection `menu`) can be either:
- Simple priced item
  - `rate` (number): selling price shown to customers
  - `price` (number): kept equal to `rate` for compatibility
  - `mrp` (number, optional): strike-through MRP
  - `discountPercent` (number, optional): percent shown on UI

- Variant priced item
  - item has `variants` array
  - each variant object has:
    - `name` (string): variant display name. In admin, "Size Variant" appends suffix at the end, so names look like:
      - "Spicy Half"
      - "Family Pack Full"
      - "Combo 6 Pcs"
    - `rate` (number): selling price
    - `price` (number): equal to `rate`
    - `mrp` (number, optional)
    - `discountPercent` (number, optional)

Customer-side behavior:
- `fetchMenuCategories()` in `src/lib/data.js` “explodes” items that contain variants into separate customer-visible items.
- Each variant becomes its own item card with:
  - `name` = "{VariantName} {ItemName}" (or whatever is stored/derived)
  - pricing set from the variant

2) Pricing auto-calculation rules (admin-driven, affects what customer sees)

Admin UI computes the missing field when possible:
- If Rate + Discount are entered → MRP can be derived.
- If MRP + Discount are entered → Rate can be derived.
- If MRP + Rate are entered → Discount can be derived.

Rounding is to whole rupees for derived values.

3) Payment endpoints (Razorpay)

These are Vercel serverless functions under `api/`.

A) Create order
- File: `api/create-order.js`
- Endpoint: POST /api/create-order
- Body: { amount: number, items?: [...], cartChecksum?: string }
- Returns: { orderId, amount, currency }

Note: The file contains a TODO security note: server should recompute/verify the amount from server-known cart data (do not trust client amount in production).

B) Verify payment signature
- File: `api/verify-payment.js`
- Endpoint: POST /api/verify-payment
- Body: { orderId: string, paymentId: string, signature: string }
- Returns: { valid: boolean }

C) WhatsApp notifications
- File: `api/send-whatsapp.js`
- Endpoint: POST /api/send-whatsapp
- Uses WhatsApp Cloud API (requires env vars WA_TOKEN, WA_PHONE_NUMBER_ID)

4) Environment variables (high level)

- RAZORPAY_KEY_ID
- RAZORPAY_KEY_SECRET
- CORS_ORIGIN (comma-separated allowed origins)
- WA_TOKEN
- WA_PHONE_NUMBER_ID
- (optional) WA_TEMPLATE_DEFAULT_NAME, WA_TEMPLATE_DEFAULT_LANG

5) Firestore rules / schema

Menu is stored in `menu` collection (one doc per category) with `items[]`.
This app expects public read access to menu unless rules are locked down.
